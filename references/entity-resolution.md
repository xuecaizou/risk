# 简称、旧称和关键词匹配

目标是匹配用户想查的法律实体，而非单纯找到名称相似的公司。投资查询必须等主体确定后再执行。

1. 保留原始输入，去除两端空格用于搜索；不要删除“集团”“股份”等足以区分实体的词。用户给出信用代码或已选定详情链接时优先核对该唯一标识。
2. 用原始简称或关键词搜索风鸟，读取候选卡片的全称、信用代码、地区、状态及可见的曾用名、上市/集团信息。不要把搜索排序当作身份证明。
3. 匹配依据依次参考：用户给定的唯一标识；全称精确匹配；页面明确列出的曾用名/简称；用户给定地区、行业、股票代码等上下文与候选的一致性。
4. 只有一个合理候选且页面证据能解释简称与该主体的对应时，可直接选择，并在进度说明“按××有限公司查询”。每次实时核对当前搜索结果和企业ID，不固定历史查询主体或旧entid。
5. 一个简称可能对应集团、上市公司、地区子公司或多个同名实体。存在此类实质歧义时列出2至5个主要候选，附全称、地区、信用代码及区分点，让用户选择；保留搜索结果，暂不采集投资列表。一次问清，收到选择后继续，不重复确认。
6. 只有成功响应明确给出空列表/零条，或正常网页确认无结果，才按无结果处理。非成功业务码（包括曾出现的3000000）先核对请求，不直接认定企业不存在。无结果时可尝试去除用户附加的“公司/集团”等口语尾缀或使用页面已显示的曾用名，但保存每次查询词。若仍无可信候选，请用户补一个区分信息（地区、行业、股票代码或统一社会信用代码），不要编造全称。

不维护写死的真实企业别名表。品牌、集团统称与其上市公司不一定是同一主体；“母公司”的推测不能代替页面证据。

在查询元信息中记录。以下名称均为虚构示例，不代表真实查询结果：

```json
"entity_resolution": {
  "input_name": "示例集团",
  "search_terms": ["示例集团"],
  "selected_name": "示例集团有限公司",
  "method": "unique_supported_candidate",
  "reason": "说明本次实际读取到的匹配证据",
  "user_confirmed": false
}
```

`user_confirmed`仅在用户确实选定时为true；候选唯一而自动继续不假冒用户确认。例子中的名称不能作为其他查询的固定答案。
